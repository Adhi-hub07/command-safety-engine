Three verdicts. Zero guesswork.

The engine sits between your keyboard and the kernel, inside bash and zsh. It inspects every command you type and answers in real time — then explains itself in plain English.

ALLOW · exit 0

Safe, whitelisted or low risk. Runs instantly with zero added latency — your daily commands cost ~0 ms.

git status  →  runs immediately
WARN · exit 1

Risky. The hook keeps your line and waits — type the exact same command again to confirm you really meant it.

chmod -R 777 /var/www  →  confirm to run
BLOCK · exit 2

Destructive. Refused outright — the line is cleared before anything executes. Explained with rule, MITRE mapping and a safer rewrite.

rm -rf /  →  never executes
// Pipeline

How it works

Hybrid AI — three layers of defence-in-depth working together, all on-device, all offline.

1

Preprocess & tokenize

Normalization, alias expansion, $VAR resolution, then a bashlex tokenizer parses words, pipes, redirects and substitutions.

2

Rule engine — deterministic

20 MITRE-mapped rule groups (R001–R020) match instantly and can never be argued out of a block.

3

ML classifier

scikit-learn GradientBoosting trained on 1,379 real + synthetic commands classifies safe / risky / destructive across 20 features.

4

Local LLM — Qwen 2.5 3B

Invoked only for ambiguous or novel commands to write a plain-English explanation and a safer alternative. Runs on Ollama, fully offline.

5

Decision fusion

Rules and ML are fused into a 0–100 risk score. A critical rule always blocks regardless of ML confidence — the model can never talk the system out of a block.

6

Output + audit

Rich CLI or JSON verdict, plus a privacy-preserving audit log that stores only truncated SHA-256 hashes — never plaintext commands.

// Why it exists

A terminal is the most powerful — and least protected — interface on Linux

One mistyped or copy-pasted command (rm -rf /, a fork bomb, a curl | bash chain) can destroy data or hand an attacker the machine. No mainstream OS ships a safety layer between the keyboard and the kernel — until now.

🔌

100% offline

No cloud APIs, no telemetry, no data egress. Aligned with India's sovereign OS (AtmaNirbhar) mission — fully functional on air-gapped government networks.

🧠

Hybrid AI

Deterministic rules + trained ML classifier + local LLM. Three independent layers that cross-check each other in milliseconds.

⚡

Fast

Rules + ML path ≈ 0.34 ms mean (p95 0.61 ms). Full pipeline ≈ 3 ms. Whitelisted daily commands cost ~0 ms.

🛡️

Safety-first override

A single critical rule match blocks regardless of ML confidence. The model can never talk the system out of a block.

📖

Explains & teaches

Every warning shows the matched rule, its MITRE mapping, why it matters, and a safer rewrite like rm -rf /path/to/folder.

🔐

Privacy-preserving audit

~/.csengine/audit.log stores only truncated SHA-256 hashes — incidents are correlatable, but commands can never be recovered.

🐧

BOSS OS & Ubuntu/Debian

Works on the Indian government's GNU/Linux and standard distros, on both bash and zsh.

🎯

Honest ML numbers

5-fold cross-validation on deduplicated data — no cherry-picked single splits. See the real numbers below.

🧪

Optional bubblewrap sandbox

Dry-run untrusted downloads safely before anything touches the real filesystem.

// Setup on Linux

Install on Linux in 3 steps

Works on Ubuntu, Debian and BOSS OS. Python 3.8+, ~1 GB RAM (3 GB with the LLM).

Install prerequisites

sudo apt-get update
sudo apt-get install -y git python3 python3-venv python3-pip curl
Optional (for LLM explanations): curl -fsSL https://ollama.com/install.sh | sh then ollama pull qwen2.5:3b-instruct-q4_K_M

Clone & install

git clone https://github.com/Adhi-hub07/command-safety-engine.git
cd command-safety-engine
bash setup.sh  — venv + deps + model training + Ollama + shell hooks
source ~/.bashrc

Verify

csengine status  — rules, model, LLM availability
csengine check "rm -rf /"  → BLOCK (exit 2)
csengine check "chmod -R 777 /var/www"  → WARN (exit 1)
csengine check "git status"  → ALLOW (exit 0)

# CLI reference csengine check "<command>" # analyze one command csengine check --json "<command>" # analyze, print JSON csengine check --audit "<command>" # analyze + write audit log csengine install-hook [bash|zsh] # install shell preexec hook csengine status # model / LLM availability csengine --version # kill-switch export CSENGINE_DISABLE=1 # temporarily disable the hook unset CSENGINE_DISABLE # re-enable

End-to-end verified with a real-PTY test that drives an interactive shell and proves a destructive dd never executes and a risky chmod requires confirmation: python3 scripts/test_hook_pty.py (bash + zsh, ALL PASS) and bash scripts/verify_demo.sh (17/17 checks).
